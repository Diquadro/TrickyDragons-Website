# Handbook Update Prompt

## Comprehensive Multi-Turn Update Process

```
Let's begin a multi-turn update process for this project handbook and related documentation. This will be a structured conversation to ensure comprehensive and precise updates.

TURN 1 - INITIAL ANALYSIS:
Analyze the code in the project and the current handbook.md file. Use parallel tool execution for maximum efficiency. Provide a high-level report identifying:
- New dependencies or technologies added to the project
- Changes in directory or file structure
- New npm scripts or modifications to existing commands
- Changes in configurations or environment variables
- New components, services, or APIs (pay special attention to analytics and tracking systems)
- Database or migration changes (examine the latest migrations thoroughly)
- Updates to the build or deployment process
- New code conventions or best practices adopted
- Missing information or outdated sections

ANALYSIS METHODOLOGY:
1. Start with semantic searches for: "package.json dependencies", "analytics", "new features", "migrations"
2. Use parallel grep searches for: npm scripts, environment variables, API endpoints, database changes
3. Examine the ai_journal.md file if it exists to understand recent changes and their context
4. Read the latest database migrations (check files with highest numbers)
5. Compare current codebase structure with handbook documentation

TURN 2 - UPDATE PLANNING:
Based on the initial analysis, present a detailed update plan, indicating:
- Sections of the handbook to add (prioritize missing major systems like analytics)
- Sections to update (focus on outdated technical information)
- Sections to remove (outdated references, non-existent features)
- Proposed structural changes
- Technical accuracy issues to address
- Completeness gaps to fill (especially for complex systems)
- Consistency improvements needed
- Usability enhancements to implement
- AI Journal entries to incorporate into permanent documentation

PRIORITIZATION:
- HIGH: Major missing systems (analytics, new APIs, database changes), AI Journal insights
- MEDIUM: Updated dependencies, configuration changes, build process updates
- LOW: Minor corrections, style improvements

TURN 3 - SECTION-BY-SECTION UPDATE:
Update the handbook section by section following these guidelines:

STYLE AND TONE:
- Technical but accessible style
- Active and direct voice
- Concise but comprehensive
- Expert perspective guiding a new developer
- Professional but not formal tone

STRUCTURE:
- Respect the existing hierarchical organization
- Group related information together
- Maintain consistency across similar sections

CONTENT:
- OBJECTIVE: Comprehensive and accurate guide for developers
- CONTEXT: For both onboarding new developers and as a reference
- KEY FOCUS: Architectural patterns, code conventions, and operational flows
- AVOID: Passwords/credentials, subjective commentary, non-technical jargon
- ENRICHMENT: Include practical examples wherever possible to illustrate concepts
  For example:
  - Code snippets showing how to use key components
  - Sample commands with expected outputs
  - Step-by-step examples for common workflows
  - Before/after examples for configurations
  - API request/response examples with realistic data

TURN 4 - UPDATE THE HANDBOOK UPDATE PROCESS:
Review this handbook_update_prompt.md file itself and suggest improvements:
- Are the prompt instructions still relevant and effective?
- Could the update process be more efficient?
- Does it reflect the latest project needs and AI capabilities?
- Does it account for complex systems like analytics and tracking?
- Should the AI Journal concept be enhanced?
- Provide updated content for the handbook_update_prompt.md file if needed

TURN 5 - FINAL REVIEW:
Conduct a final review to ensure:
- Overall consistency and readability
- Technical accuracy throughout (especially for complex systems)
- Completeness of all sections (verify major systems are documented)
- Logical structure and organization
- No duplicate or contradictory information
- Sufficient practical examples in complex sections
- AI Instructions section is accurate and helpful
- All relevant AI Journal entries have been incorporated into the handbook

TURN 6 - DELIVERY:
Produce the definitive versions of:
1. The updated handbook.md file in English
2. The updated handbook_update_prompt.md file in English
3. Archive the current ai_journal.md content (move to ai_journal_archive_YYYY-MM.md) and reset ai_journal.md to working template

All content must be delivered in English, regardless of the original language of the documents.

AI JOURNAL PROCESSING:
During the update process:
- Review all entries in ai_journal.md to understand recent changes
- Incorporate relevant insights and decisions into the appropriate handbook sections
- After incorporating the information, archive the current ai_journal.md content
- Reset ai_journal.md to a clean working template for future AI development cycles
- The AI Journal should be treated as a "consumed" resource that gets reset after each handbook update

## AI Journal Integration

The AI Journal serves as a critical component for:

1. **Development Context**: Understanding what changes AIs have made during development cycles
2. **Decision History**: Reviewing the reasoning behind architectural choices made between handbook updates
3. **Change Documentation**: Having detailed records of implementations and modifications
4. **Update Efficiency**: Faster handbook updates by understanding what has changed and why
5. **Knowledge Continuity**: Ensuring architectural decisions are preserved even when development team changes

The AI Journal follows a **consumption model**:
- AIs working on the project continuously update it during development
- During handbook updates, the journal is reviewed and its content incorporated
- After handbook updates, the journal is archived and reset for the next cycle
```
